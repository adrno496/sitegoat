# Utiliser Journal 360 unifié V7 localement

## Import principal

Importer un HTML autonome via **Importer une édition**, destination Bibliothèque. Le bloc inerte `<script id="unifiedData" type="application/json">` contient le contrat `journal360.unified`, `schemaVersion: 7`, `scheduleId: paris-v7-8`, fuseau `Europe/Paris`. Le schéma exécutable et ses contrôles sont dans `src/data/unified.ts`. Le [schéma JSON structurel](JOURNAL360_UNIFIED_V7.schema.json) se régénère avec `node scripts/export-unified-schema.mjs` sous Node 24 ; les contrôles sémantiques Zod (temps, références, comparabilité, budgets et empreintes) restent obligatoires. Le programme est 08/10/12/14/16/18/20/22 ; le plan historique 08/16/21 reste distinct. Aucun changement de tâche ChatGPT n’est effectué.

Les huit exemples dans `public/examples/unified/` sont **SYNTHÉTIQUES**, datés du 19 octobre pour ne pas déclarer comme vérifiée une édition future du 20 octobre. Ils se régénèrent avec `node scripts/generate-unified-examples.mjs`. Chaque HTML contient aussi un `editionData` de repli pour l’index magazine historique. Le bloc unifié validé fait autorité dans V7 ; le repli n’est pas une preuve de complétude V7 pour un ancien client.

Les fichiers `edition-0800.json`…`edition-2200.json` décrivent les enveloppes de test ; le parcours principal d’import V7 est **HTML**. Le parcours d’import JSON existant reste réservé au contrat Future v1. Ne pas importer ces enveloppes V7 comme dossiers Future.

## Contrat et limites

- Une journée = `journal360-day-YYYY-MM-DD`, une révision explicite, un créneau publié, une fenêtre de couverture et des créneaux inclus/manquants. L’état déclaré COMPLETE ne suffit pas : les originaux des créneaux précédents doivent avoir été reçus pour contrôler le cumul. Une reconstruction documentaire contrôlée n’est pas automatiquement certifiée par cette version.
- `items[]` utilise des `eventId` stables. Les corrections ont un motif, une date et des sources référencées. Une première apparition ne peut pas être réécrite silencieusement. Les omissions d’événements restent signalées et les anciens articles restent indexés.
- `sourceWatch` distingue les quatre univers sans dupliquer les originaux. Les identifiants locaux ou titres ressemblants ne suffisent jamais à fusionner des événements. Le dédoublonnage entre univers exige un `eventId` commun, une date identique et une ancre V7 ; les références aux anciennes versions restent conservées.
- Les `economicSnapshots` portent zone FR/EU/US/CN, série/fournisseur/définition/unité/fréquence/période, valeur, date statistique, publication et vérification, sources, lecture/risque/contre-argument. La comparaison exige une unité et une définition identiques. Aucune courbe n’est fabriquée avec des séries absentes. Une valeur réaffichée n’est pas une nouvelle publication.
- `futureInsights` distingue observations/hypothèses/scénarios/signaux ; un jalon futur ne peut pas être observé. Les `futureDocuments` optionnels au sens fonctionnel (tableau vide autorisé) sont des dossiers v1 stricts réellement qualifiés, pas un magazine renommé. Le bouton d’adaptation exporte un JSON validé ; l’import Future est ensuite manuel avec confirmation. Aucune transaction entre bases n’est prétendue atomique, aucune note Future n’est déplacée.
- Les `promptAssets` contiennent le texte Markdown **intégral**, identifiant, titre, produit, lien d’événement, nom, MIME et SHA-256 facultatif. Si un checksum fourni ne correspond pas au contenu UTF-8, l’import est refusé. Les exports recalculent une empreinte. Le téléchargement est demandé par un bouton hôte ; l’application ne prétend pas constater son enregistrement final.
- Sérialiser le JSON avec `<` encodé en `\u003c`, ne jamais concaténer du contenu brut contenant `</script>`. Les valeurs affichées dans l’UI native restent du texte non fiable, sans HTML injecté. Le lecteur V7 démarre sans scripts ; les autorisations et le comportement legacy ne sont pas élargis.
- MIME HTML/XHTML ou type générique texte/binaire accepté avec validation du contenu ; un MIME image incohérent est refusé sans écriture. HTML UTF-8 ≤ 10 Mo ; 20 fichiers / 100 Mo par lot ; métadonnées V7 ≤ 2 Mo, 60 000 nœuds / profondeur 14 ; ≤ 2 000 événements, 100 publications économiques, 200 jalons, 50 prompts de 200 000 caractères, 5 dossiers Future par enveloppe. Le budget global peut donc être atteint avant les maxima individuels. Un rejet garde les données existantes et permet de corriger le fichier source.

## Parcours

**Aujourd’hui** montre la dernière publication reçue, son état de cumul, les lacunes et les dates. Si la dernière journée disponible est ancienne, cela est indiqué. La synthèse, les priorités et les actions viennent des données importées ; les emplacements absents restent explicitement vides. Les chiffres synthétiques sont marqués et ne constituent aucun diagnostic réel.

La sous-navigation de l’accueil ouvre **Économie**, **Chronologie IA**, **Mes prompts .md**, **Recherche globale**. Les neuf destinations historiques restent présentes sur ordinateur et sur les deux lignes de navigation mobile. La recherche textuelle historique et les confirmations Google sont conservées ; la recherche globale est un index textuel local supplémentaire, pas un modèle sémantique. Les sources/signaux/scénarios des dossiers Future sont lus par lots de 25, uniquement dans ce parcours. Les premiers résultats s’affichent par 30, avec affichage supplémentaire. Les notes privées restent dans l’ancien parcours de recherche et ne sont pas ajoutées aux questions Google.

Les cartes Sentinel et les articles unifiés donnent accès aux prompts. Pour les anciens HTML, **Voir les prompts VS Code** inspecte l’original. Les variantes `textarea/pre#fullPrompt`, `#vscodePrompt`, `#promptVscode` et les sections de prompt identifiées sont reconnues. Plusieurs prompts ont chacun leur carte ; aucun bouton de téléchargement n’est produit si aucun contenu n’a été trouvé. Voir / Copier / Sélectionner / Télécharger restent des gestes explicites. Le texte n’est jamais envoyé automatiquement à Google.

La bibliothèque de prompts privilégie les dernières éditions unifiées par journée et les dossiers Sentinel historiques. Les versions anciennes et leurs prompts restent dans les originaux via l’historique ; elle ne crée pas de copies persistantes. Les listes de documents sont plafonnées à 100 résultats et les vues chronologie à 50 jalons, 20 dossiers, pour préserver la lecture : affiner la recherche ou ouvrir l’atlas complet pour les autres documents.

## Sauvegardes, anciens appareils et rollback

IndexedDB reste aux versions journal 4 et Future 1 ; aucune migration SQL/IndexedDB ni suppression. Les octets originaux, UUID, notes et favoris restent dans les mêmes tables. Les sauvegardes historiques ZIP v1/v2 restent lisibles. Un ZIP contenant V7 est explicitement marqué **formatVersion 3** ; son contrôle SHA, ses limites et sa fusion non destructive restent actifs. Les métadonnées V7 ne sont pas supprimées par un snapshot simulé d’ancien client sur le même original.

**Mettre à jour tous les appareils avant tout usage réel de V7 avec le cloud.** Un ancien client peut refuser un ZIP v3 ; il ne faut pas annoncer une compatibilité bidirectionnelle inexistante. Aucun test n’a appelé Supabase réel. Ne déployer ni migrer quoi que ce soit sans accord distinct. Le Futur garde sa sauvegarde séparée v1 ; les deux ZIP sont nécessaires pour restaurer les deux univers avec leurs notes.

Rollback local : conserver d’abord les ZIP journal et Future, les HTML V7 et le diff de cette branche. Ouvrir le code de référence dans un dossier séparé issu de `/tmp/journal360-v7-reference-43f8b56.tar` ou d’un worktree détaché de `43f8b56`. Les données de profil réel n’ont pas été sauvegardées par l’agent. Ne jamais faire `reset --hard`, `git clean`, supprimer IndexedDB ni écraser les originaux. Le vieux code ne sait pas restaurer V7 : garder l’archive v3 et utiliser le nouveau code dans un profil de test pour la restaurer. La restauration des archives historiques et des données synthétiques V7 est testée ; un rollback fonctionnel complet sur un appareil réel contenant V7 reste à valider avant publication.
